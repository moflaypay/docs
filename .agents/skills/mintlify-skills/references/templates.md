# Templates

Start with the smallest template that fits the page's job. Delete sections that do not help the reader.

## How-to guide

Use for a specific task with a clear end state.

````md
---
title: "Enable [task or feature]"
description: "Enable [task or feature] to [outcome]."
---

One sentence on what the reader will accomplish.

## Prerequisites

- Required setup
- Required permissions
- Required earlier steps

## [Action-focused heading]

1. Go to [specific location].
2. Change [specific setting].
3. Save or run [specific command].

```language
# Copyable example
```

## Verify the result

Describe how success looks.

## Troubleshooting

- **Problem**: Fix
- **Problem**: Fix

## Related tasks

- Link to the next useful task
````

## Tutorial

Use for hands-on learning with a clear outcome.

````md
---
title: "[Verb] [specific outcome]"
description: "Learn how to [specific outcome] by [approach]."
---

State what the reader will learn and what they will have at the end.

## Prerequisites

- Required knowledge
- Required tools or accounts
- Optional time estimate

## Step 1: [First action]

Explain the action and why it matters.

```language
# Copyable example
```

## Step 2: [Second action]

Keep the sequence linear. Point out milestones.

## Step 3: [Third action]

Minimize optional branches.

## Next steps

- Related tutorial
- Useful how-to
- Deeper reference or explanation
````

## Explanation

Use for concepts, system behavior, and design choices.

````md
---
title: "About [concept]"
description: "Understand [concept] and how it works in [product]."
---

Define the concept and explain why it matters.

## How [concept] works

Explain the mechanics in plain language.

## Why it works this way

Describe constraints, tradeoffs, or design choices.

## When to use [concept]

- **Use when**: Good fit
- **Use when**: Another good fit
- **Avoid when**: Better alternative exists

## Relationship to other features

Connect the concept to adjacent parts of the product.

## Common misconceptions

- Misconception and correction

## Further reading

- Related explanation
- Related how-to
- Reference page
````

## Reference

Use for precise technical lookup.

````md
---
title: "[Feature or API] reference"
description: "Reference for [feature or API] properties, parameters, limits, and options."
---

One sentence describing what this feature or API does.

## Properties

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `example` | `string` | Yes | Clear behavior-focused description |

```

## Responses or behavior

- Precise outcome
- Edge case
- Constraint or limit

## Related pages

- Explanation page
````
